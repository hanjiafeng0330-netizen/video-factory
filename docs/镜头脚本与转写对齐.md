# 镜头脚本：画面与台词的对齐

> 对应实现：`app/domain/shot_script.py`、`app/domain/transcript.py`、
> `app/adapters/asr/faster_whisper.py`、`app/capabilities/transcribe/capability.py`
> 对应测试：`tests/unit/test_shot_script.py`（23 项）、`tests/unit/test_asr_normalization.py`
> 相关文档：`docs/镜头切分策略.md`

---

## 1. 问题

预处理产出三样彼此独立的东西：镜头边界、关键帧、音轨。它们**分开时对视频理解几乎
没有价值**——模型看到一串时间区间、一堆图片、一堆句子，但不知道哪句配哪个画面。

而设计文档对下游的要求恰恰都建立在这个对应关系上：

- 6.3 视频理解要判断「视频钩子、痛点、证据、情绪和行动号召」；
- 6.4 脚本拆解要「还原原视频叙事结构」；
- 6.3 还要求「提取为什么可能有效的证据，而非只输出泛化总结」。

「这个钩子是靠画面立起来的还是靠话术立起来的」——这个判断只有在画面与台词对齐之后
才可能做出。所以预处理与视频理解之间需要一个组织层。

---

## 2. 结构

```
镜头 i ── 时间区间 [start_ms, end_ms)
       ├─ 关键帧资产          画面证据
       ├─ 画面描述            视觉理解（T3-3）填充，当前为空
       ├─ 台词                落在该区间内的转写句
       └─ 语音占比            区分口播型镜头与画面型镜头
```

对应 `ShotScriptEntry`。整体是 `ShotScript`，附带 `has_transcript`、
`speech_ratio`、`silent_shot_count` 等整体信号。

### 为什么它是计算视图而不是产物

`build_shot_script()` 是 `(镜头列表, 转写)` 的**纯函数**，刻意不落成第三个产物：

- 存下来就会出现「预处理改了、转写改了，但镜头脚本还是旧的」这种漂移，而漂移的
  症状是 LLM 分析依据了过期数据，**没有任何报错**；
- 它的两个上游都带确切版本号，视频理解产物只需引用那两个上游，血缘依然完整，
  任何时候都能按同样的纯函数重算出一模一样的视图。

### 与「分镜」的区别

设计文档 6.8 的 `Storyboard`（分镜）在**生成侧**：脚本 → 分镜 → 视频任务，描述
「要拍成什么样」。本文档在**分析侧**：热点视频 → 镜头脚本，描述「原视频是什么样」。
两者结构相似但方向相反，混用一个类型会让血缘图上出现语义相反的同名节点。

## 3. 对齐规则

### 3.1 一句台词归属哪个镜头：按时间重叠最大，不拆分文本

拆分会切断词与语义。「这个东西其实根本不用洗」被切成「这个东西其实」和
「根本不用洗」，两半单独看都会被误读；而 ASR 的词级时间戳精度不足以支撑可靠的
切分点。

### 3.2 跨镜头的句子必须被标记

`spans_shot_boundary`。这**不是瑕疵而是重要信息**：剪辑常故意让口播跨越画面切换
来维持连贯，「话没说完就切画面」本身就是一种创作手法。视频理解在判断叙事结构时
需要看到它，否则会把一个连贯的表达误读成两段独立内容。

### 3.3 纯画面镜头必须保留

无台词的镜头在营销视频里承担明确功能：产品特写、字幕板、前后效果对比。**不能因为
没有台词就把这个镜头从结构里省略**，否则视频理解会看到一个不连续的叙事。

### 3.4 语音占比只累加落在本镜头内的部分

跨镜头的长句若整句计入，会让占比超过 100%。占比的用途是区分口播型与画面型镜头，
超过 1 的值会让这个信号失效。

### 3.5 「无转写」与「无人说话」必须可区分

`has_transcript` 显式标记。**「该视频无音轨」「转写失败」「确实全程无人说话」是三种
不同情况**，前两种必须能和第三种区分开，否则视频理解会把技术故障当成创作手法来
解读。转写能力在无音轨时直接报错而不是返回空转写，正是为此。

### 3.6 关键帧不足时留空，不错位

关键帧触顶（`max_keyframes`）时后续镜头的 `keyframe_asset_id` 为 `None`，而不是
把帧顺移。错位会让模型看着 A 的画面读 B 的台词，**而它仍会给出一份读起来很合理的
分析**——这类错误不报错，只以「分析不准」的形式出现，极难追溯。

### 3.7 没有句子被静默丢弃

`unassigned_line_count()` 暴露未归属句数。正常应为 0（镜头覆盖全片）；非 0 意味着
上游镜头列表有缺陷，必须暴露而不是丢句。

## 4. 序列化给模型：`render_for_analysis()`

输出形如：

```
总时长 9641ms，共 3 个镜头，语音占比 92%
[镜头0] 0-3240ms（3240ms）
  画面：（待视觉理解）
  台词：很多人以为洗脸要用热水
[镜头1] 3240-6480ms（3240ms）
  画面：（待视觉理解）
  台词：其实温水才对,热水会破坏皮肤屏障（跨镜头）
```

**这是数据序列化，不是提示词。** 它只描述事实（时间、画面、台词），不含任何指令、
角色设定或分析要求——那些属于提示词注册表（T1-5），必须先经业务评审再落库
（开发计划 1.3 节）。把指令混进序列化函数会让提示词绕过评审与版本管理。

有一条测试专门守这条边界：`test_render_carries_no_instructions` 断言输出里不出现
「请」「你是」「分析」「输出」「要求」「任务」这类指令词。

## 5. 转写（ASR）

### 5.1 为什么独立于预处理

预处理是纯本地、零费用、可无限重跑的；转写可能走云服务、按时长计费。合在一起会让
「换灵敏度重切一次镜头」也顺带重跑一次转写，而重跑要花钱就没人敢重跑——设计文档
3.1 要求独立重跑，那条要求只有拆开之后才真的成立。

另一个收益：转写换模型不需要重跑抽帧与切分，反之亦然。

### 5.2 为什么一期默认本地模型

`faster-whisper`，默认 `small` + `int8`，CPU 推理。

| | 本地 faster-whisper | 云 ASR |
|---|---|---|
| 边际成本 | 0 | 按时长计费 |
| 重跑 | 无限次 | 每次花钱 |
| 素材外传 | 无 | 有，涉及设计文档 13.3 |
| 中文准确率 | 可用 | 更高，标点更好 |
| 速度 | CPU 上较慢 | 快 |

热点分析是内部动作且需反复重跑，零边际成本比准确率高几个点更重要；不外传素材直接
规避了一类版权与合规风险。云 ASR 走同一个 `SpeechRecognizer` 协议接入，通过配置
切换，不影响任何业务代码。

模型尺寸选择：`tiny`/`base` 在中文上错字明显，`medium` 以上在 CPU 上慢到不实用。
需要更高准确率应当切云 ASR，而不是在本地堆模型尺寸。

### 5.3 繁简归一化

**实测问题**：whisper 对中文常输出繁体。同一段普通话口播得到
「很多人以為洗臉要用熱水」。

**为什么必须处理**：转写会流进 LLM 分析和人工审核。繁体字形会让脚本模板里出现混杂
字形，人工审核也被迫先做一遍字形转换。

**处理方式**：用 OpenCC 做确定性的 `t2s` 转换，**不是**用 `initial_prompt` 去引导
模型。理由有两条：`initial_prompt` 会改变模型行为、结果不确定；而且它属于提示词，
按项目规则必须先经业务评审再落库。繁简转换是纯文本归一化，可测、不影响识别结果
本身。

素材确实来自港台平台时应当关掉，因此它是参数（`normalize_to_simplified`）而不是
硬编码。归一化状态体现在模型标识里（`faster-whisper:small+t2s`），否则无法回答
「这条脚本依据的转写是否做过繁简转换」。

### 5.4 其他刻意不做的事

- **不做说话人分离。** 一期素材以单人口播为主，diarization 的收益远小于它带来的
  失败模式。
- **不做除标点外的文本后处理。** 转写应当是「模型说了什么」的忠实记录；纠错与改写
  属于人工修订，必须产生新版本而不是就地覆盖。
- **不因低置信度丢句。** 自动丢弃会让转写出现无声的空洞，比留着一句可疑的话更难
  排查。置信度用于在审核页标出可疑句。
- **VAD 过滤静音段**是开启的，用于抑制 whisper 在长静音上产生幻觉重复句——那是该
  模型系列的典型失败模式。

## 6. 验收记录

用 macOS `say` 合成三句中文口播，配三段硬切画面（各约 3.2 秒），端到端结果：

```
转写：faster-whisper:small+t2s 识别语言 zh，3 句 / 41 字
  [    0-2500 ms] conf=0.85  很多人以为洗脸要用热水
  [ 2500-6500 ms] conf=0.85  其实温水才对,热水会破坏皮肤屏障
  [ 6500-9700 ms] conf=0.85  记住这一点,你的皮肤会好很多

镜头0 0-3240ms      台词：很多人以为洗脸要用热水
镜头1 3240-6480ms   台词：其实温水才对,热水会破坏皮肤屏障（跨镜头）
镜头2 6480-9641ms   台词：记住这一点,你的皮肤会好很多

未归属句数 0   纯画面镜头 0   整体语音占比 92%
血缘：transcript ← preprocess_result ← hot_video
```

第二句（2500–6500ms）跨越 3240ms 的镜头边界，被正确归属到重叠更大的镜头1 并标记
为跨镜头。

用真实语音（而非构造的假转写）验证是刻意的：假转写永远不会暴露「whisper 输出繁体」
这类问题。
